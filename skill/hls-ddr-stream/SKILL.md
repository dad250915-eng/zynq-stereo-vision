# DDR扫描核加速

适用于逐像素/逐样本访问DDR的HLS核。输入至少包括实际源码、接口数据宽度/步长、时钟、综合II、AXI突发证据、可用BRAM与实测时间。缺少证据时给待验证假设，不直接承诺延迟。

先计算扫描下限 N/(f×每拍样本数)，区分流水线II和DDR停顿。II=1只说明无停顿时可每拍接收一次；随机读写、条件读取、共享端口或背压都可能使墙钟时间更长。

无邻域依赖的核优先评估“连续读→小FIFO→局部运算→连续写”，保留行步长和有效宽度差异；把整帧有效性分支移到扫描循环外须保持无效帧原有语义。存在3×3等邻域的核再评估行缓存，明确边界填充值和最后两行排空，不能把整帧灰度放片上当作默认方案。

并行优化先画依赖：消费者所需输入是否已经稳定？能否使用更早完成的等价数据？若让两个IP共享只读mask，保持其帧号和生命周期直到所有消费者完成；显示分支仍需等待自己的底图完成。启动消费者再启动生产者，核对AXIS握手/last/user、超时和无效目标分支。

资源估算用缓存深度×位宽，加上HLS推断的端口/分区开销，再以综合报告校正。并行后DDR竞争可能抵消收益，所以保存同输入、同频率的优化前后实测，分别列单核、重叠区间与端到端时间。

输出：瓶颈假设及对应证据、最小接口改动、资源预算、功能不变量、需综合/上板验证的项。不要只按总IP时间相加计算吞吐。

本项目观察：D的红框判断简单，但逐像素掩膜访存与依赖使其约121ms；改为连续读写并让I读B已完成的mask后，历史日志D约10.9ms且与G/H/I有约10.8ms重叠。数据来自不同历史片段，不能当作严格受控基准。见 ../../report/optimization_evidence.md。

可复用提示词：
> 请根据以下HLS源码、II与AXI报告、实测日志，区分计算瓶颈、DDR停顿和串行依赖。给出保持接口语义的最小改动，说明缓存需求和重叠执行的输入生命周期。性能估计写清频率、像素数、带宽假设，并列必须实测的边界。
