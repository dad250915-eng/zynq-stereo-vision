# 双目帧与坐标契约

在改动双目或双流图像架构前，追踪真实端口→DDR槽→标定文件→算法参考图→显示坐标。字段名称LEFT/RIGHT可能与物理RX编号相反，不能按编号猜测。

写出一张契约表：两路身份、参考图、视差符号/定点格式、有效宽高、字节/像素单位的行步长、裁剪起点、帧号、buffer写者与读者生命周期。用源码连接和已验证样本交叉确认。不把软件获得稳定帧等同于曝光同步已证明。

裁剪必须覆盖完整视差搜索和Census邻域，保留可配置SGM上下文。两图同矩形裁剪时仍需确认参考坐标和搜索方向。稀疏mask不意味着SGM自动跳过空白：若仍按全幅发送，计算规模仍按传入宽高决定。只有区域参数改变并被读取端采用，才改变实际流量。

裁剪后的(u,v)恢复为原图(x0+u,y0+v)后再用原标定计算毫米XYZ。毫米X/Y依赖Z，不可把像素质心提前计算结果当作原可靠视差样本算法的等价物。

显示上下翻转应在显示写回处做一次；不要为修正观看方向去翻转算法mask、修改视差符号或改相机坐标。核对文字字模的行列位序，特别用2/3/5/6/7等非对称字形检查，1/8的视觉正常不足以证明位序正确。

对持续写DDR的采集，完整帧的有效性不仅依赖“复制前检查”。证明读期间写者不会覆盖所选槽；若用停车/准入保护，明确生效确认、保护失效检测和释放时机。多消费者共享mask或descriptor时，直到最后一个消费者结束才允许生产者覆盖。

本项目契约实例：RX1=LEFT，RX0=RIGHT，RIGHT_RECT参考，d=uR-uL；彩图步长1920个32位字，有效1280×720；灰度步长1280字节。此实例只用于说明填写方式，不可直接套到别的板卡。见 ../../docs/architecture.md。

可复用提示词：
> 在提出改动前，请从连接与地址表逐段证明两路身份、参考方向和buffer所有权，列出裁剪恢复坐标与显示翻转各自发生的位置。没有证据的关系标注待确认，并说明最小验证样本，不按变量名字推断真实相机。
